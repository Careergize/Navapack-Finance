## Implemented

- Foundation: standalone typed mock provider, cancellable asynchronous loading, reusable frame/card/state components, explicit preview gate, responsive navigation, visible mobile close control, focus containment and Escape dismissal.
- Design: existing Navapack logo, AppShell-matched green frame, dark #102d24 sidebar, mint #b7efbd active navigation, pale page background, rounded cards and existing typography/action conventions. Styles are scoped under b1-root. No operational component/provider is imported, avoiding operational API side effects.
- Dashboard: cash balance, receivables, payables, net cash flow, monthly receipts/payments chart and accessible chart-data table, overdue attention summaries, draft count, receivables ageing and recent fictional activity.
- Interaction: October/November sample period, local refresh, retry/restore, explicit sample/loading/empty/error/unavailable/unassessed/denied scenario selector, and read-only chart disclosure.
- Isolation: no Django/Frappe requests, browser tokens/storage, operational data providers, authentication, financial forms, posting, approval, activation, configuration, export or real record creation. Upcoming navigation entries are disabled and have no functioning destination.

All record IDs start DEMO-. All parties and the Preview company are fictional. Sample UGX amounts, dates and illustrative cash opening value are in-memory fixtures, not company/master/opening-balance configuration. Summary values derive from those fixtures and exclude drafts, future records and future settlements. Changing period changes the mock data scope. These are not a trial balance, financial statement or complete accounting ledger.

The client's CA / Finance Manager remains responsible for future real company/accounting configuration through separately approved Navapack React screens. Production Finance availability, explicit entitlement and disabled posting remain untouched. Technical authentication and company authorization stay documented future work.
